## Existing D1 records: do not lose your earlier waiting list

This code does not read or move your production D1 records automatically. Pause new submissions during cutover, retain a backup, and export `SELECT * FROM waitlist_signups` as private JSON through your D1 tools. With the Supabase migration applied and server-only `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` set in a secure local shell, run:

```sh
node scripts/import-d1-waitlist.mjs /private/path/waitlist-export.json
```

The script accepts a plain array or Wrangler-style JSON results, checks every row before importing, and refuses incomplete contact records/phone numbers rather than inventing information. Old records need valid international numbers; manually verify incomplete records first. Imports preserve the earlier consent version/date, mark records as legacy, leave demographics unknown, and do not assert new adult/guardian consent or send any emails. Duplicate emails are retained once. Completed batches can safely be rerun. Verify totals against the private export before opening the new form. Never commit exports. Existing D1 records are not deleted.

If the old Resend sender already sent emails that UTC day, wait until the next reset before enabling the new sender, or reserve the remaining day conservatively in `ea_waitlist_budget`. The new Supabase counter cannot reconstruct earlier D1/provider use. Old queued D1 jobs are no longer consumed by the new Worker and should be reconciled separately to avoid repeating old confirmations.

## Form fields and analytics

- Required: adult contact’s name, surname, email, selected phone country and cellphone, adult confirmation and email consent.
- Phone dropdown covers the supported numbering countries with their calling codes. `libphonenumber-js` normalizes national/international input; e.g. South Africa + `0821234567` becomes `+27821234567`, Zimbabwe + `0772123456` becomes `+263772123456`. Country-specific significant zeros are preserved where required. Invalid numbers and a mismatch between a full international number and the selected country are rejected.
- Optional: intended wearer gender (Female/Male/Prefer not to say) and age range. Ranges are **12 and under, 13–17, 18–19, 20–23, 24+**, without overlapping boundaries or a missing age 12. No exact birthday is collected. Under-18 interest requires guardian confirmation; names/phone/email are the adult’s details. The demographic information describes intended wearers, not verified ages or identities.
- Admin table has page-aware row numbers `01`, `02`, etc., separate name/surname/phone/email columns, phone country, gender, age range, joined date and separate provider statuses. Filters for country/gender/age apply to the entire query, counts and CSV, not just the visible page. Statistics show matching rows plus an all-signups total; unknown demographics are included as “Not provided”. Country statistics are selected **phone numbering country**, not verified residence or nationality. Shared calling codes are distinguished by the selected country.
- Pages contain 50 rows; CSV exports only that filtered page. CSV cells are quoted and spreadsheet-formula prefixes neutralized. API responses are private/no-store. Contact/privacy messages still come from the existing D1 support table, with an explicit notice if that inbox is unavailable.

## Delivery and daily allowance

The database atomically saves each signup and its two independent jobs. Email is unique and normalized; duplicate submissions cannot overwrite contact details or cause another pair of messages. FormSubmit receives the default request and contact fields with subject **Join Waiting List - Name Surname**. Optional gender/age are kept in Supabase, not included in either outgoing message.

Resend sends **one** customer email per new signup, with HTML/plain text, the website palette, logo, removal link and “Exclusive Apparel × T.s Industries” signature. Each attempted confirmation reserves one of 100 UTC-day slots transactionally, even if rejected or retried. Up to 100 first-attempt confirmations can therefore be sent daily. Reset: **02:00 South African time**. Overflow remains saved and unattempted, and is processed oldest first by the five-minute Worker cron. FormSubmit notifications do not use Resend slots. Other account usage and the provider’s monthly allowance can reduce actual capacity; quota errors pause this sender until the next UTC day and are rechecked then.

Claims use row locks, per-provider pacing, short leases and attempt IDs. Resend retries keep an identical payload/idempotency key; ambiguous attempts older than 23 hours move to review before the provider’s 24-hour deduplication expires. FormSubmit has no documented idempotency guarantee, so an uncertain/interrupted/rejected notification moves to **review**, not blind automatic replay. Check Gmail/FormSubmit before any manual resend. The dashboard retry button processes due pending jobs only. Missing provider configuration leaves that provider’s work pending and does not block the other provider. Removing a signup removes queued copies but cannot recall email already in flight/delivered.

## Access controls and verification

New Supabase tables have RLS enabled and forced. `PUBLIC`, `anon` and `authenticated` are denied table/sequence access and RPC execution; only the server’s service role is granted access. The RPC is `SECURITY INVOKER` with an empty search path. Rate limits persist in Postgres with hashed IP/email identifiers. Same-origin JSON requests, bounded bodies, input validation, honeypot, admin cookie verification and CSV escaping remain active. All filters use bound data; no dynamic SQL contains request data. Application errors never log contact records or provider response bodies. Keep the service key secret: it is privileged.

The migration is tested against local PGlite PostgreSQL with explicit anon/authenticated/service roles, RLS/permission denial checks, transaction rollback, filtered statistics across pages, duplicates, phone normalization, guardian validation, leases, pacing, the 100-email cap, overflow carryover, provider failures, import and removal. Email calls are mocked. These tests do **not** certify the paused remote project or real delivery. Run Supabase advisors and equivalent verification on the restored project before launch.
